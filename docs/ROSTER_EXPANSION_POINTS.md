# Full official roster: integration points, not an implementation claim

Parent task is collecting the full official English/Simplified-Chinese roster and skill matrix in a separate workspace. Its initial2026-10-02 report says127 official heroes,107 missing from this20-hero build, including official ID155 Largo. This is incoming source inventory, not evidence that127 playable heroes or every skill has been implemented. Source endpoint: https://www.dota2.com/datafeed/herolist?language=english . Await the final matrix before producing implementation batches.

This follow-up changes no roster or backend registry. Preserve the exact existing20 array positions and string IDs. Add an explicit, versioned mapping between legacy match IDs, stable internal IDs, official numeric IDs and data positions; coordinate additions with the backend registry. Append new entries without sorting/reordering the legacy20. Old MySQL records must keep rendering the original heroes.

Suggested sequencing after the incoming matrix is complete: (1) stable registry and unsupported/implemented status ledger, (2) already-supported simple projectile/target/buff skills, (3) shared DoT/aura/dispel/channel/summon families, (4) transforms/extra-action and complex state heroes, (5) independent per-batch audit and browser acceptance. Exact heroes and batch boundaries should follow the authoritative difference matrix, not assumptions made before it arrives.
